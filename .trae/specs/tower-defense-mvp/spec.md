# 宝石塔防 MVP 规格（Tower Defense MVP Spec）

> 自然语言：中文
> 规范 ID: `tower-defense-mvp`
> 版本: 1.0.0
> 创建: 2026-08-22

---

## 1. 问题 / 用户 / 目标 / 非目标

### 1.1 问题
用户希望开发一款**开放式地图塔防**游戏：玩家在空地自由放塔，敌人以 A* 最短路径从起点涌向终点，融入「宝石塔防」的**宝石随机掉落 + 三消合成**机制，并与已有的 Go (Gin) 后端 / OpenAPI / Spine 3.8 前端渲染链路对齐。目前后端仅有用户/健康检查，前端仅完成了 Spine 资产验证页面，缺少**塔防核心玩法**。

### 1.2 用户
本阶段用户 = 本项目开发者（单人）。目标是交付一个「能玩、能扩展」的最小闭环，后续可接入 JWT 鉴权、存档、排行榜、Spine 角色皮肤替换等。

### 1.3 开发目标（MVP）
交付一个**浏览器端可玩**的塔防 Demo，同时**后端提供 JSON 配置接口**（waves/towers/enemies/gems/maps），两者通过 `/api/config/*` 按 openapi.yaml 的契约通信。

MVP 范围内功能：
- 1 张默认 24×16 网格地图（1 种地形：草地 可通行 / 石头 不可通行 / 基地 终点 / 出生点 起点），内置可运行
- A* 最短路径寻路（8 向？只允许 4 向？MVP 4 向更简单，保证塔放下去堵死时能立刻重算 + 提示「不能堵死」）
- **手动放塔**：点击空地 → 扣金币 → 放置成功；每次放塔重算所有在途敌人路径
- **塔攻击**：进入攻击范围自动锁最接近终点的第一只敌人，按塔的 DPS 发射子弹/箭矢，扣敌人 HP
- **敌人系统**：按波次生成；每个敌人按当前最短路径每帧前进一格或分数格（格子像素 × dt × speed）；到终点扣基地 HP；死亡给玩家金币
- **波次**：5~8 波递增（按 openapi 契约走后端 `/api/config/waves/{mapId}`，前端可直接用内置回退 JSON 也能跑）
- **胜利/失败**：基地 HP ≤ 0 → 失败遮罩；所有波敌人全部死亡 → 胜利遮罩；支持 重新开始 按钮
- **宝石系统**：敌人死亡按概率（宝石掉率可配置）随机掉落 3 档宝石（T1 普通 / T2 优秀 / T3 稀有）+ 5 种元素之一；点击宝石存入背包；背包里**同元素同等级 3 个宝石自动合成**更高一级（T1×3 → T2，T2×3 → T3，T3×3 → T4，MVP 最高 T4）。宝石通过「拖到塔上」或「选中塔+选中宝石+点装备」两种方式之一给塔**提升属性**（火=攻击力+20%，水=攻速+20%，风=范围+15%，土=减伤/减速效果，光=掉落率+15%）
- **UI 最小集合**：顶部 HUD（基地 HP / 金币 / 当前波次 N/M / 开始下一波按钮），左侧塔类型工具栏（2 种塔：箭塔/AOE 投石塔，造价不同），右侧宝石背包（6×10 格或可滚动），中下方 Canvas（画布 1:1 显示地图）
- **前后端契约**：实现 `/api/config/towers`、`/api/config/enemies`、`/api/config/gems`、`/api/config/waves/{mapId}` 四个 GET，返回结构符合 openapi.yaml 对应 schema；前端通过 fetch 拉取不到时使用本地硬编码兜底（保证离线也能玩）
- 角色/敌人美术在 MVP 阶段先用 **Canvas 2D 几何/颜色块**（塔=彩色圆/方，敌人=多色圆，子弹=短点），塔类型名/颜色直接复用 towers config 数据；**不使用 Spine，不阻塞玩法闭环**（spine-test.html 单独保留作为资产验证页不删除）

### 1.4 非目标（明确不做）
- JWT 鉴权 / 登录 / 存档 CRUD / 排行榜（OpenAPI 契约已定义但不实现，留到下一迭代）
- Spine 皮肤切换、攻击动作事件回调、塔 Spine 渲染（下一迭代再接）
- 多地图切换（MVP 只硬编码 1 张 mapId=1 的地图）
- 塔升级/出售（MVP 只支持放置与宝石强化）
- 多波次之间的自动准备时间 < 8 秒倒计时（改为手动点「开始下一波」更简单）
- 音效/粒子/特效
- 移动端触控适配（只要求 Chrome/Edge 桌面 1280×800+ 能玩）
- Docker build 验证（环境无 Docker，留到有 Docker 的环境）
- Node.js atlas verify 脚本验证（环境无 Node，留到有 Node 的环境）

## 2. 功能需求（Functional Requirements）

### FR1 地图与网格
- FR1.1 Canvas 网格大小：24 列 × 16 行，每格 36px → 画布 864×576
- FR1.2 格子类型：
  - `0 = 草地（可放塔，敌人可通行）`
  - `1 = 石头（不可放塔，不可通行）`
  - `2 = 出生点 S`
  - `3 = 基地 E`
- FR1.3 放塔后该格变成「有塔=不可通行」；塔被删除时（MVP 不提供删除，只提供重置游戏）变回草地可通行
- FR1.4 S 和 E 唯一；石头围成自然通道 + 至少保留一条默认路径

### FR2 A* 寻路
- FR2.1 只允许 4 向移动（上/下/左/右，避免对角线穿塔角的复杂判定）
- FR2.2 每次放塔成功、塔被移除、地图改变时：
  1. 重算 `S → E` 的最短路径（用静态 4 邻接图）
  2. **放塔前预检查**：若新塔放下去后 S→E 无路径，拒绝放塔并在 HUD 上提示「此处会堵死路径，不能放塔」，不扣金币
- FR2.3 每个敌人各自保存路径索引，每步前进像素 = `speed(格/秒) * 36px * dt`；越过格中心时进入下一段，若全局路径有变：从敌人**当前所在格子**重算到 E 的最短路径替换其路径数组，继续前进
- FR2.4 敌人走到 E，视为到达基地，扣基地 HP 并从场上移除

### FR3 放塔系统
- FR3.1 工具栏提供 2 种塔（id=`arrow_tower`、id=`cannon_tower`）
- FR3.2 点击塔工具按钮 → 光标 hover 到草地时显示半透明预览 + 可/不可 两种视觉反馈；点击草地格：
  - 若金币不足：HUD 提示「金币不足」
  - 若该格非草地：提示「只能放在草地」
  - 若会堵死路径（FR2.2 检查）：提示「不能堵死路径」
  - 否则：扣金币、该格建塔、塔立刻加入攻击循环
- FR3.3 塔攻击：每塔有 `attackRange (格) * 36px`、`attackInterval (秒)`、`damage (HP)`、`isAOE bool`、`aoeRadius px`
  - arrow_tower：单体锁最近的敌人
  - cannon_tower：AOE，命中半径内所有敌人扣相同伤害

### FR4 敌人与战斗循环
- FR4.1 敌人有 `id / name / hpMax / speed格/秒 / rewardCoin / damageToBase`
- FR4.2 波次：waves 数组，每波 `enemies: [{enemyId, count, interval秒, delay秒}]`
- FR4.3 玩家点击「开始下一波」按钮 → 前端按配置生成敌人；每 `interval` 秒放 1 只，到基地或死亡后从战场移除
- FR4.4 碰撞判定：子弹命中即扣血；AOE 圆形命中按敌人格中心距离算
- FR4.5 敌人死亡：
  - 给玩家金币
  - 按其配置 `gemDropChance`（0~1）和后端 gems config 的「掉率权重」随机决定是否掉一颗宝石（元素+等级）
  - 若掉落：在敌人死亡格中心上方画一个宝石图标，点击后进入背包
- FR4.6 HP 条：敌人头顶显示 HP 条（剩余 / 最大，宽 24px，3px 高，不同血量变色）

### FR5 宝石合成系统
- FR5.1 背包：二维网格（6 列 × 10 行，MVP 够放）
- FR5.2 每个宝石：`唯一 uid / 元素 fire/water/wind/earth/light / 等级 1~4 / base 属性加成`
- FR5.3 合成规则：背包里**相同元素**且**相同等级** **3 颗**（不要求相邻，只要数量 ≥ 3 即可按一个按钮触发） → 消耗 3 颗，生成 **1 颗同元素、等级+1** 的宝石（放入背包任意空位）；但若目标等级已经是 4 或背包满则不执行并提示
- FR5.4 装备规则：点击背包宝石 → 再点击 Canvas 上某塔 → 塔获得该宝石加成（火 damage+20% / 水 interval × 0.83 / 风 range+15% / 土 命中目标减速 30%×2秒 / 光 该塔击杀掉率加成）；MVP 每塔最多 3 槽，可重复镶不同元素；镶嵌满则拒绝并提示

### FR6 胜负 & 重开
- FR6.1 基地 HP ≤ 0 → 画布中央显示 **「💀 失败」遮罩 + 波次 N/M + 重新开始按钮**
- FR6.2 当前是最后一波 且 **场上已无存活敌人 且 不再生成敌人** → 显示 **「🎉 胜利」遮罩 + 重开按钮**
- FR6.3 重开：清空塔/敌人/背包/子弹/宝石掉落，重置基地 HP / 金币 / 波次，重新加载地图

### FR7 后端配置接口
- FR7.1 实现 4 个 GET：
  - `GET /api/config/towers` → 数组（至少 arrow / cannon 两个）
  - `GET /api/config/enemies` → 数组（至少 3 种：小兵/精英/BOSS，血量递升）
  - `GET /api/config/gems` → 5 元素 × 4 等级的属性加成表 + 掉率权重
  - `GET /api/config/waves/1` → mapId=1 的波次（至少 6 波递增）
- FR7.2 响应结构**必须匹配** `api/openapi.yaml` 里这些路径对应 schema
- FR7.3 返回头 `Content-Type: application/json`；HTTP 200
- FR7.4 前端**必须先 fetch 这些接口**，任一失败使用 `web/js/config-fallback.js` 中的硬编码兜底数据，保证后端停了前端也能玩 Demo

### FR8 UI
- FR8.1 HUD 元素：`❤️ HP 20 / 20` | `💰 金币 500` | `🌊 波次 1 / 8` | `▶ 开始下一波` 按钮
- FR8.2 左侧工具栏：箭塔（造价 100，伤害 15 范围 3） / 炮塔（造价 200，AOE 伤害 25 范围 2 半径 40），点击选中后再点 Canvas 放塔；右键或 ESC 取消选中
- FR8.3 右侧宝石背包：每格可点击装备 / 合成按钮位于背包上方「🔮 一键合成」（每次按下扫描所有满足 3 同元素同等级的组合，从低等级开始合成，直到没有可合成为止）
- FR8.4 画布悬停草地显示可放塔高亮（绿半透明），悬停石头/塔/路径显示禁止高亮（红半透明）
- FR8.5 顶栏 + Canvas + 背包 三栏布局，浏览器缩放 100%、窗口 ≥ 1366×768 时无横向滚动条

## 3. 非功能需求（Non-Functional Requirements）

### NFR1 性能
- NFR1.1 60 敌人 / 20 塔 同屏时 Chrome 桌面 60FPS（16ms/帧），JS 主线程单帧不超过 8ms
- NFR1.2 放塔后重算 A* ≤ 3ms 单次（24×16 网格不大）
- NFR1.3 合成扫描背包 ≤ 1ms

### NFR2 代码与工程
- NFR2.1 前端纯 HTML + 原生 ES6（不引入 npm，不打包），沿用当前 `web/` 结构
- NFR2.2 前端游戏主逻辑文件：`web/js/td-game.js`（1500 行以内；超过就拆 td-*.js 但先拆 TD 再决定）
- NFR2.3 后端新增 handler 文件放到 `internal/handler/config.go`，不污染 health/user.go
- NFR2.4 router 新增 `/api/config/*` 注册放在和 `/api/users` 同组内；CORS/logger/中间件沿用现有
- NFR2.5 所有新增 JS 函数均有 1 行 JSDoc 简介；Go 代码导出函数有 godoc 注释
- NFR2.6 不提交日志/二进制：沿用现有 .gitignore

### NFR3 兼容
- NFR3.1 只需要最新 Chrome/Edge（Chromium ≥ 120）
- NFR3.2 Canvas 2D，不依赖 WebGL / 非 Spine

### NFR4 可维护性
- NFR4.1 游戏内常量（格子数/像素/初始金币/HP）集中在 `web/js/td-game.js` 顶部 `TD.CONFIG`，不散落
- NFR4.2 配置数据（塔/敌人/波次/宝石）结构完全按接口返回，前端无需自己维护另一份 schema（回退版也按同 schema）

## 4. 约束 / 依赖 / 假设 / 未决问题

### 4.1 约束
- 操作系统：Windows
- 浏览器：Chromium 系最新版本
- 当前环境：无 Node.js / 无 Docker（不影响 MVP；如果要跑 verify_atlas.js 或 docker build 会分别阻塞）
- Go 1.25 / Gin v1.12（已存在 go.mod）

### 4.2 依赖
- 后端：Gin（已在 go.sum）
- 前端：无新增第三方依赖；纯原生 Canvas 2D

### 4.3 假设
- 用户只做单人本地浏览器 Demo，不需要多人/房间匹配
- MVP 后端配置为**静态 JSON**（直接在内存 map 写死），不做数据库持久化；下一步迭代再接存储
- 玩家不会用"放塔堵住路径，然后敌人无限卡原地"当刷宝石外挂；MVP 已通过 FR2.2 预检查堵死路径放置来规避

### 4.4 未决问题（待确认，但不阻塞 MVP）
- [ ] 后续迭代是否把 Canvas 2D 视觉换成 Spine？（预期：是）
- [ ] A* 4 向 vs 8 向后续是否升级 8 向？（MVP 保持 4 向不变）
- [ ] 宝石是否有「分解/出售换金币」？（MVP 不提供）
- [ ] 塔出售/升级后续是否加？（MVP 不提供）

## 5. 验收标准（Acceptance Criteria）

> 类型只能是 `rule` 或 `rubric`，每条有独立可观测结果/证据来源。

### 5.1 玩法规则 AC
- **AC-1 (rule)**：打开 `http://localhost:8080/web/index.html`（或新页 tower-defense.html），不做任何操作，就能看到 HUD / 工具栏 / 宝石背包 / Canvas 地图四套 UI 正常，无控制台报错。→ 证据：浏览器 DevTools Console 0 error + 屏幕截图
- **AC-2 (rule)**：点击箭塔工具 → 点击任意草地 → 塔成功出现；金币 -100；之后再放同样塔若金币 0 会提示「金币不足」。→ 证据：放塔前后 HUD 金币差值 + 控制台/浮层提示
- **AC-3 (rule)**：在 S→E 默认路径上尝试放一排堵死所有路径 → 最后一块草地**无法**放下塔，浮层提示「不能堵死路径」，金币不扣。→ 证据：截图放塔失败高亮 + 提示
- **AC-4 (rule)**：点击「开始下一波」→ 敌人按配置 interval 逐个从 S 生成，沿最短路径到 E，到达时 HP - damageToBase。→ 证据：录屏或 100ms 间隔截图，显示敌人沿最短路径前进
- **AC-5 (rule)**：塔攻击范围内有敌人时自动扣血；敌人 HP ≤ 0 消失，玩家金币 + rewardCoin；敌人有 HP 条显示。→ 证据：击杀前后 HUD 金币 + 敌人消失截图
- **AC-6 (rule)**：连续按「开始下一波」直到最后一波结束，场上无敌人 → 出现胜利遮罩；若基地 HP ≤ 0 → 出现失败遮罩；遮罩上点击「重开」回到初始状态（金币/HP/波次重置，塔/敌人/背包清空）。→ 证据：胜利/失败两种遮罩的截图各一张 + 重开后 HUD 数据回到默认。
- **AC-7 (rule)**：敌人死亡掉落宝石（至少打 20 只，应出现至少 1 颗，概率由配置决定）。点击宝石 → 进入背包。背包中 3 颗同元素同等级宝石存在时，点击「一键合成」生成 1 颗同元素升 1 级的宝石，原 3 颗消失。→ 证据：背包截图合成前后对比（count 3→1 & level+1）
- **AC-8 (rule)**：点击背包 1 颗宝石 → 再点 Canvas 上某塔 → 塔该属性数值发生配置中描述的变化（如火宝石 +20% 攻击力：塔下弹出浮字「+20% 攻击」，且该塔之后一次攻击 damage 提升）。→ 证据：塔属性 log 对比 + 命中伤害数字不同。
- **AC-9 (rubric - scale 0-2, threshold ≥ 1)**：手感维度：放塔响应、敌人移动、攻击反馈、胜负判定的综合流畅度与 bug 数量。
  - 2 分：全程 3 分钟游玩不出现白屏/卡死/敌人卡住；操作反馈及时（≤100ms）
  - 1 分：1 次以内出现非致命 bug（如偶尔子弹穿怪、合成一次没反应但重试 OK），不影响通关流程
  - 0 分：出现白屏/卡死/敌人不走/无法放塔等致命问题

### 5.2 前后端契约 AC
- **AC-10 (rule)**：Go 服务器启动后，分别 `GET /api/config/towers`、`/api/config/enemies`、`/api/config/gems`、`/api/config/waves/1`，返回 HTTP 200，`Content-Type: application/json`，且 JSON schema 符合 `api/openapi.yaml` 对应响应 schema（至少关键字段存在且类型对：towers[] 每元素有 `id / name / cost / range格 / damage / attackInterval秒 / isAOE / aoeRadiusPx` 等）。→ 证据：PowerShell curl / 浏览器 Network Response 截图
- **AC-11 (rule)**：关闭后端服务器后，刷新 Demo 页，仍能**完整**游玩（数据由 fallback config 提供，流程不阻塞）。→ 证据：后端停了仍通过 AC-4 / AC-5 / AC-6 一条。

### 5.3 性能 AC
- **AC-12 (rule)**：Chrome Performance 面板录制 10 秒游戏（场上 40 敌人 / 15 塔），平均 FPS ≥ 55。→ 证据：Performance 面板 FPS 曲线截图。
